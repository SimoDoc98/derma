# Contributing to DERMA

Thank you for your interest in DERMA. This document will grow as the project matures;
for now it describes how DERMA handles datasets, which matters for anyone adding a
dataset loader or writing tests.

## Working with datasets

DERMA estimates its profiles from public EDA datasets, but it never ships or fetches 
the data itself. Please follow these rules when you add or modify a dataset loader.

1. **No automatic downloads.** DERMA never downloads anything on its own. Many datasets
   require registration or accepting a licence, and the user must remain in control of
   what is downloaded and where.
2. **The user provides the original archive.** The user downloads the dataset from its
   official source and places the original archive, unmodified, in a data folder of
   their choice. The folder is passed as a function argument or through the
   `DERMA_DATA_DIR` environment variable. Never hard-code paths.
3. **DERMA prepares the data.** Starting from the archive, the loader:
   - verifies its checksum, so that everybody works on the same version of the data;
   - reads the files it needs directly from the archive, without extracting it;
   - runs the preprocessing;
   - saves the ready-to-use data in the same data folder, so the preprocessing runs only once.
4. **One module per dataset.** Each dataset has its own module. When a loader
   reproduces an existing preprocessing pipeline (for example the original MATLAB
   scripts used to build DERMA's reference profiles), it must replicate the same steps
   in the same order: resampling, filtering, segmentation, condition labels.
5. **Document every difference.** If a step cannot be reproduced exactly (e.g. a
   resampling filter that differs between MATLAB and SciPy), describe the difference and
   its expected numerical impact in the module docstring.
6. **Never commit data.** Raw or derived data (`.mat`, `.npz`, `.csv`, extracted
   archives, preprocessed files) must never enter the repository. Also check that
   nothing derived from a dataset ends up in test fixtures.

## Tests and examples without datasets

Tests, examples and documentation must run on a clean machine without any dataset.
Use synthetic signals generated by DERMA itself, or tiny hand-made fixtures that are not
derived from real recordings. Tests that need a real dataset (for example to check a
loader against reference outputs) must be skipped automatically when the data folder is
not available, and never run in continuous integration.
